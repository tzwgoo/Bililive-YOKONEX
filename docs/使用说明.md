# BiliLive-YOKONEX 使用说明

## 1. 程序用途

本程序支持两种直播消息来源，实时监听直播间中的：

- 官方 `open-live`
- 第三方房间消息流 `LiveDanmaku`

两种模式都能接收以下事件：

- 礼物
- 弹幕
- 点赞

当监听到指定礼物时，程序会根据本地映射规则，自动调用下游 `WEBSOCKET_API` 发送对应 `commandId`。

## 2. 运行前准备

你需要准备以下信息：

- 下游指令服务的：
  - `WS URL`
  - `UID`
  - `TOKEN`

如果你要使用官方模式，还需要：

- `APP_ID`
- `BILI_ACCESS_KEY_ID`
- `BILI_ACCESS_KEY_SECRET`
- 主播身份码 `code`

如果你要使用第三方模式，还需要：

- 直播间房间长 ID `room_id`

## 3. 配置文件说明

### 3.1 `.env`

把根目录下的 `.env.example` 复制为 `.env`，然后填写真实配置。

示例：

```env
APP_ID=1234567890123
BILI_ACCESS_KEY_ID=your_access_key_id
BILI_ACCESS_KEY_SECRET=your_access_key_secret
GIFT_MAPPING_PATH=config/gift_command_mappings.json
```

字段说明：

- `APP_ID`：B站开放平台项目 ID
- `BILI_ACCESS_KEY_ID`：开放平台访问 Key ID
- `BILI_ACCESS_KEY_SECRET`：开放平台访问 Key Secret
- `GIFT_MAPPING_PATH`：礼物映射文件路径，默认是 `config/gift_command_mappings.json`

补充说明：

- 官方模式需要这组 `.env`
- 第三方模式不依赖开放平台 `.env`
- 下游指令通道参数不再从 `.env` 读取
- 你需要在页面中手动输入 `WS URL / UID / TOKEN` 并点击“登录指令通道”
- `sendCommand` 所需的 `userId` 会优先使用下游服务 `loginResult` 返回的 `data.userId`
- 如果下游没有返回 `userId`，程序会尝试从页面填写的 `UID` 自动推导
- 例如 `UID=game_123456` 时，会自动推导出 `userId=123456`

### 3.2 礼物映射文件

编辑 `config/gift_command_mappings.json`。

示例：

```json
[
  {
    "gift_id": 1001,
    "gift_name": "小花花",
    "command_id": "player_hurt"
  },
  {
    "gift_name": "牛哇牛哇",
    "command_id": "player_attack"
  }
]
```

匹配规则：

- 优先按 `gift_id` 匹配
- 如果 `gift_id` 没命中，再按 `gift_name` 匹配
- 命中后发送：

```json
{
  "type": "sendCommand",
  "userId": "登录返回或从页面 UID 自动推导出的 userId",
  "commandId": "映射中的 command_id"
}
```

## 4. 源码方式启动

### 4.1 安装依赖

```bash
pip install -r requirements.txt
```

### 4.2 启动程序

```bash
uvicorn app.main:app --reload
```

然后打开：

- [http://127.0.0.1:8000](http://127.0.0.1:8000)

## 5. EXE 方式启动

如果你已经拿到打包后的目录：

1. 把 `.env.example` 复制成 `.env`
2. 填好 `.env`
3. 编辑 `config/gift_command_mappings.json`
4. 双击 `BiliLive-YOKONEX.exe`
5. 程序会自动打开浏览器
6. 在页面里输入 `WS URL / UID / TOKEN`
7. 点击“登录指令通道”
8. 在页面的“监听模式”里选择：
   - `官方 open-live`
   - `第三方房间消息流`
9. 官方模式输入主播身份码 `code`
10. 第三方模式输入直播间房间长 ID `room_id`
11. 点击“启动监听”

## 6. 页面操作流程

1. 打开本地页面
2. 选择监听模式
3. 如果是官方模式，确认“配置状态”为“已加载”
4. 输入 `WS URL / UID / TOKEN`
5. 点击“登录指令通道”
6. 官方模式输入主播身份码 `code`
7. 第三方模式输入直播间房间长 ID `room_id`
8. 点击“启动监听”
9. 观察礼物、弹幕、点赞事件，注意卡片上的“官方 / 第三方”来源标签
10. 送出已配置的礼物
11. 查看“最近指令 ID”和“最近指令结果”
12. 使用结束后点击“停止监听”

## 7. 日志位置

运行日志会写入：

- `logs/app.log`

如果你是运行 `exe`，日志目录就在 `exe` 同级的 `logs` 文件夹下。

## 8. 常见排查

### 8.1 页面显示配置未加载

请检查 `.env` 是否存在，且以下字段已经填写：

- `APP_ID`
- `BILI_ACCESS_KEY_ID`
- `BILI_ACCESS_KEY_SECRET`

说明：

- 这个问题只会影响官方模式
- 如果你当前使用的是第三方模式，可以先忽略它

### 8.2 礼物到了，但没有发指令

请检查：

1. `config/gift_command_mappings.json` 里是否存在对应礼物规则
2. 礼物名或礼物 ID 是否与真实事件一致
3. 页面中的 `WS URL / UID / TOKEN` 是否填写正确并已登录成功
4. 下游 `WEBSOCKET_API` 服务是否可连通

### 8.3 页面显示“下游指令通道未登录”

说明礼物命中了映射，但当前页面会话里还没有登录下游指令通道。请检查：

- 是否已经点击“登录指令通道”
- 页面输入的 `WS URL / UID / TOKEN` 是否正确

### 8.4 页面显示“指令发送失败”

优先检查：

1. 页面填写的 `WS URL` 是否可访问
2. 页面填写的 `UID` 和 `TOKEN` 是否正确
3. 下游服务是否已经成功返回 `loginResult`
4. 如果下游不返回 `userId`，请确认页面 `UID` 能正确推导出纯数字用户 ID

### 8.5 第三方模式没有收到消息

优先检查：

1. `room_id` 是否填写为直播间房间长 ID，而不是短号或用户 UID
2. 当前直播间是否正在开播
3. 本机网络是否能正常访问 B 站直播消息流

## 9. 自己重新构建 EXE

在项目根目录执行：

```powershell
.\build_exe.ps1
```

构建完成后，产物目录在：

- `dist/BiliLive-YOKONEX/`

主要文件：

- `dist/BiliLive-YOKONEX/BiliLive-YOKONEX.exe`
- `dist/BiliLive-YOKONEX/.env.example`
- `dist/BiliLive-YOKONEX/config/gift_command_mappings.json`
- `dist/BiliLive-YOKONEX/docs/使用说明.md`
