# 波形编辑器拖拽反馈与分段配置折叠设计

日期：2026-06-05

## 背景

当前 Vue 版波形编辑器已经具备连续时间轴、A/B 强度拖拽、时长拖拽和分段表单编辑能力，但和旧版前端相比，仍然存在两类体验落差：

1. 拖拽时的反馈不够强，用户不容易快速确认当前正在改哪一段、数值改到了多少。
2. 分段逐行表单默认展开，占据较多纵向空间，弱化了“先在时间轴里编辑”的主路径。

本次优化只聚焦这两点，不扩展到分段重排、多选、框选、跨段联动等更重的编辑器能力。

## 目标

1. 提升波形时间轴拖拽编辑的即时反馈，让用户更容易感知当前操作对象和当前数值。
2. 将分段逐行配置默认收起，降低页面初始信息密度，把可视化时间轴明确为主编辑入口。
3. 保持现有数据结构、保存接口和页面信息架构不变，避免额外业务风险。

## 非目标

1. 不修改蓝牙波形保存 API 协议。
2. 不改动波形库页面整体布局和左侧列表结构。
3. 不实现分段重排、框选、多段联动、撤销重做。
4. 不引入 canvas 重绘或全新编辑器内核。

## 方案对比

### 方案 A：轻量增强

- 保留现有连续时间轴 DOM 结构。
- 补拖拽态视觉反馈、手柄即时数值、分段选中态和参考线。
- 分段逐行表单默认折叠，需要时手动展开。

优点：

- 改动集中在 `WaveformEditorPanel.vue` 和对应测试。
- 风险最小，最适合当前“对齐旧版体验”的目标。

缺点：

- 仍然基于现有手柄式交互，不会变成完全重做的专业时间轴编辑器。

### 方案 B：中度增强

- 在方案 A 基础上，加顶部“当前分段信息条”，显示当前分段序号、时长、A/B 值。
- 拖拽时增强当前段与全局波形总览联动。

优点：

- 反馈更完整。

缺点：

- 增加额外状态和展示层，复杂度更高。

### 方案 C：重做编辑器

- 重写时间轴交互模型，靠近音频/视频编辑器模式。

优点：

- 潜力最大。

缺点：

- 明显超出本轮范围，风险高。

## 选择

采用方案 A。

原因：

1. 能直接解决“拖拽不够顺手”和“分段配置太占空间”两个当前痛点。
2. 可以最大限度复用现有 Vue 波形编辑组件和测试。
3. 更适合在已有主分支基础上做一轮低风险优化。

## 用户体验设计

### 1. 拖拽反馈增强

在现有连续时间轴基础上增加以下反馈：

1. 当前被拖拽的分段整体高亮。
2. 当前被拖拽的手柄显示更强烈的激活态。
3. 拖拽 A/B 强度时，手柄文案实时显示最新值，例如 `A 72`、`B 118`。
4. 拖拽时长时，时长手柄实时显示最新值，例如 `260 ms`。
5. 当前分段显示一条水平参考线，帮助判断强度位置。
6. 非当前分段轻微降低视觉权重，但不隐藏。

设计原则：

1. 反馈优先服务当前操作，不制造过多新控件。
2. 尽量复用现有 DOM 和样式层级，不改底层事件模型。

### 2. 分段配置默认折叠

分段逐行表单从默认展开改为默认折叠。

交互规则：

1. 页面初次进入时，分段配置区默认收起。
2. 提供一个明确按钮：
   - 收起时显示 `展开分段配置`
   - 展开时显示 `收起分段配置`
3. 折叠后仅隐藏逐行表单，不影响：
   - 顶部统计信息
   - 时间轴拖拽编辑
   - 新增分段按钮
   - 保存、复制、删除波形按钮
4. 展开状态仅在当前页面会话内生效，本轮不做 localStorage 记忆。

这样可以保证默认视图更聚焦在时间轴本身，同时仍保留精确数值编辑入口。

## 组件设计

主要修改文件：

- `frontend/src/components/waveforms/WaveformEditorPanel.vue`
- `frontend/src/tests/components.waveform-editor.spec.ts`

可选少量联动文件：

- `frontend/src/pages/WaveformLibraryPage.vue`

### `WaveformEditorPanel.vue`

新增本地状态：

1. `activeSegmentIndex`
   - 当前高亮的分段索引
2. `dragField`
   - 当前拖拽字段：`channel_a / channel_b / duration_ms`
3. `isStepListExpanded`
   - 分段配置是否展开，默认 `false`

状态来源规则：

1. 开始拖拽时设置 `activeSegmentIndex` 和 `dragField`
2. 结束拖拽时清空拖拽态
3. 点击展开按钮时切换 `isStepListExpanded`

### 模板结构调整

保持现有卡片结构，但做以下调整：

1. 在时间轴区域的每个分段上增加激活态 class。
2. 手柄文案从静态 `A / B` 改为动态数值文本。
3. 在当前分段插入参考线元素。
4. 将逐行分段表单包进可折叠容器。
5. 在 `step-toolbar` 附近增加折叠切换按钮。

## 样式设计

样式目标：

1. 当前分段更亮、更聚焦。
2. 非当前分段轻微降噪，但保持可见。
3. 激活手柄有更强阴影、描边或颜色强化。
4. 收起后的页面纵向高度明显下降。

建议样式策略：

1. `timeline-segment.is-active`
   - 提高背景对比
2. `waveform-track.is-dragging .timeline-segment:not(.is-active)`
   - 降低透明度
3. `timeline-handle.is-active`
   - 增强阴影和缩放
4. `timeline-guide-line`
   - 使用细线和半透明强调
5. `step-list[hidden]`
   - 通过条件渲染或 `v-show` 控制

## 数据流

不改变现有对外事件：

1. `update-step`
2. `update-waveform-name`
3. `add-step`
4. `duplicate-step`
5. `remove-step`
6. `save-waveform`
7. `duplicate-waveform`
8. `delete-waveform`

只在组件内部补充展示状态，不影响页面层和 store 层接口。

## 测试设计

采用 TDD，先补组件测试再改实现。

重点新增或更新测试：

1. 默认折叠分段配置
   - 初始不显示逐行分段表单
   - 点击按钮后展开，再点后收起
2. 拖拽时激活态
   - 按下 A/B 或时长手柄后，当前分段带激活 class
3. 拖拽时数值反馈
   - 手柄文本根据当前 step 值变化
4. 当前段参考线渲染
   - 仅当前激活段显示参考线

已有测试保留：

1. 连续时间轴渲染
2. 强度拖拽事件触发
3. 时长拖拽事件触发

## 风险

1. 拖拽过程中如果组件频繁重渲染，可能造成激活态闪烁。
2. 手柄文案变长后，窄分段里的布局可能拥挤。
3. 默认折叠后，如果展开入口不够明显，少数用户可能一时找不到逐行编辑。

## 风险缓解

1. 激活态状态尽量使用简单 `ref` 管理，避免复杂派生。
2. 对过窄分段保留最小宽度和文本压缩策略。
3. 展开按钮放在分段工具栏显眼位置，文案明确使用“分段配置”。

## 验收标准

1. 波形编辑页默认不展开逐行分段配置。
2. 用户可以手动展开和收起分段配置。
3. 拖拽 A/B 强度时，当前分段和当前手柄有明显激活反馈。
4. 拖拽过程中手柄能实时显示当前值。
5. 拖拽时长时，时长手柄能实时显示当前毫秒值。
6. 现有 Vitest 和前端构建继续通过。
