# 控制台布局与事件工作区重组设计文档

## 1. 背景

在 `Vue + Ant Design Vue` 迁移完成第一阶段后，当前前端虽然已经完成了技术栈切换，但页面职责仍然延续了旧版结构：

- 主控台同时承担监听参数、连接操作、状态展示和日志展示。
- `IM 规则` 页面只覆盖命令价格档位。
- `蓝牙 Studio` 同时承载波形库、波形编辑和蓝牙事件规则。

这套结构在功能上可用，但信息架构已经暴露出几个问题：

- 一级导航仍然以“实现页面”划分，而不是以“用户任务”划分。
- 蓝牙规则和波形编辑混在同一页，用户需要频繁在“规则”和“资产”两个心智模型之间切换。
- 主控台缺少真正的“首页”定位，既不像概览，也不像专门的操作台。
- 随着 `IM` 和蓝牙能力同时增长，旧的页面拆分方式会继续放大页面长度与复杂度。

本次改版目标不是新增业务能力，而是重新组织现有能力，使页面结构更符合使用习惯。

## 2. 目标与范围

### 2.1 目标

- 将顶层导航改造成统一后台布局：`左侧菜单 + 顶部标题栏 + 右侧内容区`。
- 将一级导航收敛为用户任务导向的 3 个页面：
  - `主控台`
  - `事件配置`
  - `波形库`
- 将原有 `IM 规则` 和蓝牙事件规则合并为一个“事件配置”页面，并通过两个 Tag 在 `IM` 与 `蓝牙` 间切换。
- 将蓝牙波形管理从原 `蓝牙 Studio` 中拆出，成为独立的“波形库”页面。
- 将旧前端主控台中高频的监听参数与启动控制保留在新主控台中，但以“压缩控制面板”的形式呈现。

### 2.2 非目标

- 本阶段不统一后端 `IM` 规则与蓝牙规则的数据协议。
- 本阶段不新增新的事件类型、规则类型或波形能力。
- 本阶段不重写现有 SSE、轮询或状态同步机制。
- 本阶段不额外增加“设置”“概览”“系统管理”等新一级页面。

## 3. 总体方案

采用“导航重组 + 页面职责重分配”的方案，在不推翻现有后端接口的前提下完成前端信息架构重构：

- 顶层布局统一为后台控制台样式。
- 主控台从“全功能页面”转为“概览 + 高频控制 + 日志”的首页。
- 事件配置页承接所有事件规则编辑能力。
- 波形库页承接所有波形资产管理能力。

核心原则：

- `主控台` 负责看状态、做高频控制、看日志。
- `事件配置` 负责定义“什么事件触发什么输出规则”。
- `波形库` 负责管理“规则绑定到的波形资产”。

## 4. 一级导航与路由设计

### 4.1 一级菜单

左侧一级菜单固定为：

- `主控台`
- `事件配置`
- `波形库`

菜单只保留一级页面入口，不额外加入二级导航或页面内分组目录。

### 4.2 路由

新的前端路由调整为：

- `/` -> `主控台`
- `/events` -> `事件配置`
- `/waveforms` -> `波形库`

兼容性处理：

- `/command/studio` 重定向到 `/events`
- `/bluetooth/studio` 重定向到 `/waveforms`

这样可以兼容旧入口、旧收藏链接和已有页面跳转逻辑。

## 5. 顶层布局设计

统一使用新的 `AppShell`：

- 左侧：固定宽度纵向菜单
- 右侧：纵向内容区域
- 右侧顶部：页面标题栏
- 右侧主体：页面内容区

页面标题栏职责：

- 左侧显示当前页面标题与一句简短说明
- 右侧显示当前页的主操作按钮

示例：

- `主控台`
  - 标题：`直播互动监听控制台`
  - 说明：当前监听状态、连接状态、实时日志与高频控制
  - 右侧操作：可为空，或显示“启动监听 / 停止监听”的紧凑操作区
- `事件配置`
  - 标题：`事件配置`
  - 说明：管理 IM 与蓝牙的事件触发规则
  - 右侧操作：`保存 IM 规则` 或 `保存蓝牙规则`，随当前 Tag 切换
- `波形库`
  - 标题：`波形库`
  - 说明：管理波形列表、预览和分段编辑
  - 右侧操作：`新建空白波形`

## 6. 主控台页面设计

## 6.1 页面定位

新的主控台不是纯监控页，也不是完整配置页，而是“概览首页”。

它保留旧前端里高频的监听配置与启动能力，但不再承担规则编辑与波形编辑职责。

## 6.2 页面结构

主控台建议从上到下分为 4 个区块。

### 6.2.1 状态总览

展示 5 到 7 个指标卡：

- 监听状态
- 当前监听模式
- 当前输出方式
- IM 状态
- 蓝牙状态
- 当前房间 / 主播
- 最近事件时间

要求：

- 视觉上置顶
- 便于一眼看出系统是否在线
- 作为整页的第一优先级信息

### 6.2.2 监听控制区

保留旧前端中高频的监听参数和控制项，但压缩为 3 张卡片 + 一行按钮：

- `监听主参数`
  - 监听模式
  - 房间长 ID 或主播身份码
- `礼物 / 点赞触发`
  - 礼物触发模式
  - 点赞倍数
- `弹幕关键词触发`
  - 触发开关
  - 弹幕冷却秒数
  - 每用户限流窗口
  - 窗口内最大触发次数
  - 最低舰队等级
  - 弹幕关键词

下方保留：

- `启动监听`
- `停止监听`

设计要求：

- 延续旧前端实用性
- 视觉上比旧版更紧凑，不再占满整页
- 只保留高频监听参数，不引入规则编辑项

### 6.2.3 连接与设备区

分为左右两张卡：

- `IM 指令连接`
  - `WS URL / UID / TOKEN`
  - 登录
  - 退出
- `蓝牙设备`
  - 当前蓝牙连接状态
  - 扫描
  - 断开
  - 已发现设备列表

设计要求：

- 保留现在主控台中最常用的连接操作
- 蓝牙设备列表不跳到单独页面查看
- 让首页可以完成“启动前检查”

### 6.2.4 实时日志区

保留统一事件流大卡片，使用 Tab：

- 礼物
- 弹幕
- 点赞
- 互动
- 控制日志

设计要求：

- 作为主控台底部的主要动态区域
- 日志高度固定，避免页面无限增长
- 与状态区形成“静态信息 + 动态信息”结构

## 7. 事件配置页面设计

## 7.1 页面定位

“事件配置”是新的规则中心。

它不再区分旧的 `IM 规则` 页面和蓝牙规则页，而是按输出方式分成两个 Tag：

- `IM`
- `蓝牙`

Tag 只切换事件规则内容，不切换整个页面。

## 7.2 `IM` Tag 内容

`IM` Tag 下展示：

- 礼物价格档位
- 醒目留言价格档位
- 上舰价格档位
- 续费价格档位
- 固定点赞指令 ID
- 固定弹幕指令 ID

设计要求：

- 保留现有 `IM` 页面已支持的价格档位编辑体验
- 继续显示固定点赞/弹幕指令区域
- 不在本页展示监听参数
- 不在本页展示波形相关内容

## 7.3 `蓝牙` Tag 内容

`蓝牙` Tag 下展示：

- 礼物事件规则
- 点赞事件规则
- 弹幕事件规则
- 醒目留言规则
- 上舰规则
- 续费规则
- 互动事件规则

规则内容只承担：

- 是否启用
- 绑定哪个波形
- 对于礼物类规则保留价格区间字段

设计要求：

- 不在本页编辑波形本身
- 不在本页混入蓝牙设备连接逻辑
- 让用户清楚这是“事件到输出”的映射页，而不是波形资产页

## 8. 波形库页面设计

## 8.1 页面定位

波形库是独立的资产管理页，专门处理蓝牙波形。

这意味着原 `蓝牙 Studio` 中的“波形库 + 波形编辑”能力全部迁入此页，而事件规则全部迁出到“事件配置”的 `蓝牙` Tag。

## 8.2 页面结构

建议采用左右布局：

- 左侧：波形列表
- 右侧：波形详情与编辑器

左侧波形列表展示：

- 波形名称
- 内置 / 自定义标识
- 步数
- 最大强度
- 当前选中态

右侧波形编辑器展示：

- 波形名称
- 分段数 / 总时长 / 最大强度
- 波形预览
- 分段编辑
- 保存 / 复制 / 删除

设计要求：

- 保留现有已实现的波形编辑逻辑
- 继续支持内置波形只读、自定义波形可编辑
- 明确区分“资产管理”和“规则配置”

## 9. 数据流与实现边界

本次改版优先重组前端，不主动重构后端协议。

沿用现有数据来源：

- 主控台状态：
  - `/api/status`
  - `/api/command/status`
  - `/api/bluetooth/status`
- 实时日志：
  - `/api/events/stream`
  - `/api/control/stream`
- IM 规则：
  - `/api/command/studio`
- 蓝牙规则与波形：
  - `/api/bluetooth/studio`

前端仅做：

- 页面重组
- 布局重组
- 路由重组
- 现有 store / service 的重新组合

不做：

- 新增统一规则接口
- 新增统一事件配置后端模型

## 11. 迁移策略

建议分两步实施。

### 11.1 第一步：骨架与路由

- 改造 `AppShell`
- 上线左侧一级菜单
- 新增 `/events`、`/waveforms`
- 配置旧路由重定向

目标：

- 先让新的信息架构立住
- 不在第一步就同时打散所有页面逻辑

### 11.2 第二步：页面内容重组

- 主控台搬入旧监听参数区
- 事件配置合并 IM 与蓝牙规则
- 波形库拆出波形资产管理

目标：

- 逐步迁移现有功能
- 保证中间阶段始终可运行

## 12. 风险与注意事项

### 12.1 状态重复风险

主控台与事件配置页都会涉及部分共享状态，如果直接复制逻辑，容易造成两个页面的草稿状态不同步。

要求：

- 保持 `store` 为单一数据源
- 页面只做展示和编辑壳子

### 12.2 旧路由兼容风险

如果直接删除 `/command/studio` 与 `/bluetooth/studio`，会导致现有入口失效。

要求：

- 先做重定向
- 旧入口至少在一个过渡版本中保留

### 12.3 首页回潮风险

把旧监听参数搬回主控台时，容易让主控台重新变回“超长配置页”。

要求：

- 只保留高频参数
- 不把规则编辑搬回主控台
- 用卡片分组压缩表单密度

## 13. 验收标准

- 左侧一级菜单仅保留 `主控台 / 事件配置 / 波形库`
- 顶层布局变为统一后台壳
- 主控台能展示：
  - 运行状态
  - 实时日志
  - 蓝牙设备信息
  - 监听参数与启动控制
- 事件配置页具有两个 Tag：
  - `IM`
  - `蓝牙`
- 波形编辑能力已从蓝牙规则页中拆出，进入独立波形库页
- 旧路由可兼容跳转到新页面
- 现有 API 与 SSE 链路无需重写即可继续工作
